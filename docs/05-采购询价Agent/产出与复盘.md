# 05 · 产出与复盘

## 产出

一个可运行、可复现评测的脱敏项目：`agents/procure-pricer/`。零第三方依赖，三步跑通。

| 模块 | 作用 |
|---|---|
| `generate_mock_data.py` | 生成 25,920 条虚构价格记录，固定随机种子，可无限重放 |
| `intent_parser.py` | 意图门控 + 维度拆解，输出逐维决策日志 |
| `matcher.py` | 口语词 → 规范值模糊召回 |
| `query_engine.py` | 唯一查价入口，EMPTY / TOO_MANY / LIST 三分支 + 明细导出 |
| `summarize.py` | 服务端聚合：分位数 / TopN / 月度趋势 / 迷你图 |
| `eval/` | 40 条标注用例，oracle / 门控 / 无门控三方对照 |

## 量化结果

40 条用例，每条人工标注正确过滤条件，由标注条件直查库得 oracle 作为对照。

| 指标 | 门控方案 | 无门控基线 |
|---|---:|---:|
| action 一致率 | **97.5%** | 7.5% |
| 空结果率 | **7.5%** | 97.5% |
| 平均检索调用次数 | 2.08 | 2.00 |
| 门控合规率 | 97.5% | — |
| 过滤条件准确率 | 97.5% | — |

两轮迭代：v1 92.5% → v2 97.5%，修的是地区简称与「上个月」时间解析。

**最有说服力的是那个 97.5%。** 基线的空结果率 97.5% 说明：这个场景里不做约束，Agent 几乎查不出东西——约束不是优化项，是可用性前提。

## 踩过的坑

| 坑 | 归因 | 处置 |
|---|---|---|
| 「厂名+产品」连写时供应商维度丢失，厂名还污染了物料描述过滤条件 | 解析层 | 先按最长前缀定位产品词并剥离，剩余才是供应商候选 |
| `A4-70g` 被截成 `70g` | 解析层 | 规格正则顺序调整，连字符型须先于数字型 |
| 卫浴公司被误匹配成电缆厂商 | 阈值层 | 品类与供应商用不同阈值（0.30 / 0.42），不做全局统一 |
| 错别字导致召回为 0 | **知识库层** | 明确不修，归入别名表建设 |

## 如果重来

1. **评测集先于一切。** 这次是先写完代码再补标注，如果反过来，前两轮迭代的归因会更快——现在 40 条是够用，但覆盖不到多值查询（「铜芯电缆和铝合金电缆」）这类场景。
2. **阈值应该从数据里学，不该手调。** 0.30 / 0.42 是 bad case 逼出来的，换个数据域就得重调。正确做法是在标注集上扫一遍相似度分布再定。
3. **「报价是否偏高」该早做。** 业务真正要的是判定，不是区间。当前只给 P25/P75，等于把判断又推回给人。缺的是基准价口径定义，这是业务规则问题，得先和使用方对齐。

## 保留的边界

- 单次查询不支持多值，只取其一
- 横向对比（已审 vs 在审批次）未实现，需跨批次对比接口
- 错别字 / 俗称依赖别名表，不在检索层解决
- 模糊召回用字符 bigram 而非真向量模型，为的是零依赖可复现

> **脱敏声明**：数据 100% 由脚本生成，供应商与价格均为虚构；不引用任何内部文档原文、系统名或人员姓名。方法论与工程结构可复用，业务数据不可复用。
