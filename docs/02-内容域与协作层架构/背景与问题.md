# 02 · 背景与问题

## 一句话

企业知识库做到一定阶段，用户提的诉求开始混在一起——"我要存文档""我要找资料""我要跟同事对齐""跨部门要个文件"——**这些事真的是同一件事吗？**

## 场景

产品已有三大块内容沉淀：

| 内容类型 | 典型形态 | 用户诉求 |
|---|---|---|
| 知识库 | 制度、SOP、培训资料、沉淀文档 | 找得到、别过期、权限清晰 |
| 业务数据 | 报表、台账、结构化数据 | 能查、能导出、口径统一 |
| 云文档 | 外部平台上的在线文档 | 能收进来、能跳回原文 |

同时冒出大量协作类诉求：把文件发给同事看、约人一起改一版、跟一个跨部门专项的进度、知道"谁还没交"。

## 早期做法的坑

最初把协作功能直接嵌在知识库内部（文档下面挂评论、挂任务），结果：

- **权限打架**：内容权限按"谁能看这份文档"算，协作权限按"这事找谁"算，两套逻辑互相覆盖
- **重复建设**：业务数据和云文档里也需要同样的协作能力，各做一套
- **耦合到改不动**：内容结构一调整，协作功能跟着返工

## 要回答的问题

**"内容资产"和"协作动作"在产品架构上应该是什么关系？** 这个问题不解决，功能会越堆越乱。
