# 03 · 产出与复盘

## 产出物

| 产出 | 内容 | 解决的争议 |
|---|---|---|
| AI 需求分层表 | 问答型 / 处理型 / 生产型三层，含依赖能力与失败成本 | "AI 需求"没法评估和排期 |
| 边界判断三问 | 输入形态 / 是否进流程 / 错误代价 | "加聊天框还是重排工作流" |
| 能力编排链路图 | 材料 → 解析 → 检索 → 加工 → 校验 → 进流程 | 对话框与能力的关系 |
| 能力红线 | 不做通用入口、不做无边界问答、不做不可溯源结果 | 效果无法评估的风险 |
| 评估指标定义 | 命中率 / 可溯源率 / 任务完成率 | 用主观好评代替效果判断 |

## 结果

- **"知识库 + 能力编排"被确立为产品定位**，取代此前的"AI 问答工具"表述——这个定位后来成为对外介绍产品的第一句话
- 需求排期口径改变：处理型与生产型诉求不再被塞进"问答优化"里，而是作为独立的能力项评估
- 能力红线（可溯源、有边界）被写进方案，成为后续 AI 功能评审的固定检查项

## 复盘：如果重来

1. **不要先把"智能"需求归成一类**：归一类看起来省事，实际让评估和排期都做不下去。拆成能力类型后，工作量预估才第一次接近现实
2. **评估指标要一开始就定，不能事后补**：早期靠"用户觉得挺好用"判断，结果无法判断到底是哪个环节在起作用。改成命中率、可溯源率之后，才能定位问题出在检索还是解析
3. **争"对话框做多强"是伪问题**：这轮分析最大的收获是发现问题问错了。**先问 AI 该在哪个环节承担什么责任，再问界面长什么样**——顺序反了会白吵很久
