# Tech Intelligence Daily Agent

> 李梦瑶 · 海南大学数据科学与大数据技术（27 届）· 求职方向：AI 产品经理
>
> 一个科技情报日报自动化流水线：**多源采集 → 七道关卡 → 11 板块日报 → 双渠道推送**。
> 核心不是"让 AI 写摘要"，而是把日报的判断标准固化成可执行、可测试的工程。

## 先说清真实性边界

这是**一个真实运行过的内部日报 Agent 的开源复刻**。仓库里什么是真的、什么不是，一次讲清楚：

| 内容 | 性质 |
|---|---|
| 11 个板块结构、5 条质量红线、8 类故障的解法 | **真实**：来自项目运行记录 |
| 信源清单（5 个 YouTube 频道 + 23 个 X 个人账号 + 1 个官方账号） | **真实**：均为公开账号，见 [config.example.yaml](agents/tech-intel-daily/config.example.yaml) |
| 全部 Python 代码（采集 / 红线 / 生成 / 发布） | **真实可运行**：零第三方依赖，`--demo` 离线跑通，10 个单元测试通过 |
| demo 产出的日报与 `examples/sample-report.md` | **虚构**：频道名、账号名、链接全是占位符，仅演示结构 |
| 飞书 token / 群 ID / 文档 ID | **占位符**：一律 `<YOUR_XXX>` |

**demo 数据不使用真实人物或真实链接。** 把虚构内容挂在真人名字下，等于批量生产假引用——演示归演示，这条不能含糊。

## 日报的 11 个板块

顺序固定，缺失必写占位语（订阅者靠固定位置定位信息，所以不许省略板块）：

```
0. 核心动态        3-5 行纯事实
1. 今日速览        3-5 条 + 热度 🔥🔥🔥（按新鲜度与关键信号算，不凭感觉）
2. 今日金句        原文 + 出处 + 链接
3. 信息分层        ⚡必看 3 / 📖速读 5-10 / 🔬深读 2-3
4. YouTube 播客更新  频道|主题|嘉宾|核心内容|时长|链接
5. X 精选          按主题分组
6. 趋势与关联      仅 ≥2 个来源的共同话题
7. 行动建议        ≤3 条可执行
8. 待观察          单一来源、待交叉验证
9. 数据看板        今日 vs 昨日（无昨日数据写「无」，不编造）
10. 推荐阅读
附录：质量红线拦截清单（写明被拦原因）
```

→ [样例日报（虚构数据）](agents/tech-intel-daily/examples/sample-report.md) ｜ [板块规格](agents/tech-intel-daily/docs/daily-report-spec.md)

## 七道关卡：失败时怎么办比成功时更关键

| 关卡 | 检查什么 | 失败处理 |
|---|---|---|
| 1 采集 | YouTube 页面解析 + Nitter RSS，先做代理检测 | 该源跳过，不中断 |
| 2 去重 | seen_urls 滑动窗口 5000 条 | 采集阶段就跳过，避免生成后重跑 |
| 3 **新数据验证** | 今日目录存在、条目 >0、数据未过期 24h | **发通知并终止**，宁可不发也不推旧内容 |
| 4 **质量红线** | 五条红线逐条检查 | 违规条目挡在正文外，写进附录 |
| 5 生成 | 11 板块（LLM 模式 / 模板模式） | LLM 失败自动降级模板 |
| 6 **编码守卫** | 扫描 Mojibake / `\xNN` / BOM | 终止发布 |
| 7 发布 | 写入飞书文档 + 群消息摘要 | 重试 + 错误通知 |

**红线是代码，不是 prompt。** 要求模型遵守 ≠ 模型一定会遵守；模型违反时条目被 `quality_gate.py` 挡在正文之外，并写明违反原因。这是"量产质量"和"祈祷模型"的区别。

## 工程沉淀

8 类故障的完整复盘在 [`docs/engineering-notes.md`](agents/tech-intel-daily/docs/engineering-notes.md)，每条按 **现象 → 根因 → 修复 → 验证 → 预防** 记录，多数已固化成可执行检查：

- **Python 3 的 `\xNN` 双重编码**：正确 UTF-8 是 `E7 A7 91`，错误写法产生 `C3 A7 C2 A7 C2 91`；而飞书标题一旦写坏**不可更新**
- **yt-dlp 被封禁**：改用 `ytInitialData` 页面解析，递归找 `lockupViewModel`
- **中文相对时间**：`5 日前` 匹配不到英文正则，导致三天前的视频被当成今日内容
- **静默失败**：LLM 连续超时却照常推送旧日报 → 加硬性「新数据验证」关卡

## 已知局限（不遮掩）

- **真实采集链路没在本机验证过**：能验证的是 `--demo` 全流程与单元测试；29 个源的实时可用性依赖 YouTube 页面结构与 Nitter 镜像，两者都会随外部改版失效
- 表格块在飞书转换中降级为等宽文本；跨天事件聚类未实现
