## 项目一 · 需求拆解工作台

**把一堆零散业务诉求，收敛成"先验证哪一块"的结论。**

`tools/requirement-triage/index.html` — 单文件 HTML，**下载双击即用**，无需 npm、无需服务器、无需联网。

| 步骤 | 输入 | 输出 |
|---|---|---|
| 解析 | 粘贴需求清单（每行一条） | 自动拆字段 + 猜部门 |
| 打标签 | 点一下 | 需求类型（问答/处理/生产/协作/管理）+ 依赖能力 |
| 看分布 | 自动 | **纯问答 vs 需能力编排的占比**、能力依赖 Top、部门 × 类型交叉表 |
| 定验证域 | 四个维度各打 1-5 分 | 总分 + 建议（验内核 / 验边界 / 暂缓） |
| 导出 | 点按钮 | 台账 CSV、分析报告 Markdown、结构化 JSON |

**关键设计**：用关键词规则引擎而不是大模型——分类要可解释、可复现、可逐条人工修正。内置 41 条脱敏示例需求，跑出来是 29.3% 纯问答 / 70.7% 需能力编排。

→ [工具说明](tools/requirement-triage/README.md) ｜ [在线打开 index.html](tools/requirement-triage/index.html)

## 项目二 · Tech Intelligence Daily Agent

**一条可复现的科技情报日报流水线：抓信源 → 筛噪音 → 结构化抽取 → 渲染日报。**

零第三方依赖（全用 Python 标准库），`--demo` 模式不开 API key 也能跑通全流程。

```bash
cd agents/tech-intel-daily
python scripts/run.py --demo     # 零配置跑通，看 output/ 下的日报
```

| 环节 | 做法 |
|---|---|
| 筛选 | 先定**丢弃标准**：营销稿、纯观点、重复报道直接出局 |
| 分级 | 按对决策的影响分 P0（48 小时内决策）/ P1 / P2 |
| 写作 | 硬约束：禁用"革命性/颠覆/划时代"，事实与判断字段级分离 |
| 可信度 | 输出置信度，低于 0.6 进「待核实」区，不混进结论 |
| 透明度 | 日报末尾列出**今天筛掉了什么、为什么** |

**prompt 是一等公民**，放在 `prompts/` 而不是塞进代码字符串。规则模式与 LLM 模式并存：规则模式保证可复现与零成本，LLM 模式保证准确率，调用失败自动降级。
