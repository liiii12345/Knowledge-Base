# 工程笔记：踩过的坑与解法

这个项目真正的价值不在"能跑"，在下面这些坑——每一个都是线上出事后查出来的。
**问题排查方法论：现象 → 根因 → 修复 → 验证 → 预防（写成规范）。**

---

## 1. 中文乱码（Mojibake）· 严重度 🔴 高

**现象**：飞书群消息里中文显示为 `â¢ Sam Altman éé...`

**根因**：代码里用 `\xNN` 表示中文。Python 3 中 `\xNN` 创建的是 **Unicode 码点 U+00NN**，不是字节。
于是产生双重编码：

```
科 的正确 UTF-8  = E7 A7 91
错误写法产生的结果 = C3 A7 C2 A7 C2 91
```

**修复**：
1. 全部替换为直接 UTF-8 字符
2. 11 处 HTTP 请求补上 `charset=utf-8`
3. 写 `scripts/check_encoding.py`，**在发布前扫描**，把问题挡在上游

**为什么标题最危险**：飞书文档标题写入后**不可更新**，一旦以错误编码写入就永久损坏，只能新建文档。

---

## 2. 链接全部变成纯文本 · 严重度 🟡 中

**现象**：日报里所有 `[文字](URL)` 渲染成纯文字，无法点击。

**根因**：发布脚本里有一条正则：

```python
re.sub(r'\[([^\]]+)\]\(([^)]+)\)', r'\1', text)   # 只留下文字，URL 被丢弃
```

**修复**：新增 `parse_inline()`，把行内 Markdown 链接转成飞书 `text_element` 的 link 样式，
而不是删除。修复后单份报告含 15-20 个可点击链接。

**附带修复**：BOM 处理——读取报告改用 `encoding="utf-8-sig"`。

---

## 3. yt-dlp 被 YouTube 封禁 · 严重度 🔴 高

**现象**：所有视频元数据获取失败。

**修复**：改用页面解析——从频道页 HTML 里正则提取 `ytInitialData`，
再从嵌套 JSON 中递归找 `lockupViewModel` / `videoRenderer`（不写死层级，
YouTube 改结构时不容易全崩）。

**两个附带坑**：
- Tab 标题随代理 IP 变化：英文 `Videos`、中文 `影片` 都要匹配
- 中文时间文案：`5 日前`、`2 星期前` 需要单独解析（见下条）

---

## 4. 中文相对时间解析 · 严重度 🟡 中

**现象**：代理 IP 被识别为中文用户，YouTube 返回 `5 日前`、`2 星期前`，
英文正则匹配不到，结果**所有老视频都被当成新视频**进了日报。

**修复**：`parse_age_hours()` 支持中英两种单位；**识别不出发布时间的一律丢弃**
——宁缺勿滥，不能把三天前的内容说成"今日"。

```
"5 日前" -> 120.0 h    "2 星期前" -> 336.0 h
"3 hours ago" -> 3.0 h  "刚刚" -> 0.0 h
"unknown" -> None（丢弃）
```

---

## 5. Nitter RSS 返回空内容 · 严重度 🟡 中

**现象**：Twitter 采集长期返回空列表。

**根因**：没带浏览器 User-Agent 被拦。

**修复**：加 UA；并且发现**单一实例比多实例轮询更稳定**——多实例重试会
把时间浪费在一个个坏实例上。部分账号本身被 Nitter 屏蔽，属不可控，按源跳过。

---

## 6. 跨天推文重复 · 严重度 🟢 低

**现象**：同一条推文连续两天出现在日报里。

**修复**：维护 `data/seen_urls.json`，滑动窗口 5000 条 URL，
**在采集阶段就跳过**，而不是生成后再去重——后者意味着报告已经生成，重跑成本高。

---

## 7. 静默失败导致推送旧日报 · 严重度 🔴 高

**现象**：LLM 连续 5 天调用超时，定时任务仍照常推送了旧日报，订阅者以为是当日情报。

**修复**：流水线加入硬性第 2 步「新数据验证」：

1. 检查 `data/raw/<今日>/` 是否存在
2. 检查 `total_items > 0`
3. 检查数据采集时间是否在 24h 内
4. 任一不满足 → 发错误通知 → **终止，禁止推送旧内容**

**沉淀的原则**：自动化系统里，"没数据"必须比"推错数据"更容易被发现。

---

## 8. 飞书 API 限制清单

| 限制 | 说明 | 应对 |
|---|---|---|
| 标题不可更新 | PUT / PATCH 都无效 | 标题写坏只能新建文档；写入前务必校对日期 |
| batch_delete 语义 | 用 `start_index/end_index`，不是按 block_id | 保留第 0 个 block（标题），删 `1..N-1` |
| 单批写入上限 | 每批 50 个 block，过多超时 | `append_blocks()` 内部分批 |
| 权限需单独设置 | 新建文档默认不可读 | 每次新建后调用 `set_public()` |
| token 解析 | 本地环境 `resp.json()` 偶发编码异常 | 用 `json.loads(resp.text)` |

## 编码规范（项目内强制）

| 场景 | 正确 | 错误 |
|---|---|---|
| 中文表示 | 直接 UTF-8 字符 / `\uNNNN` | `\xNN`（双重编码） |
| JSON 写入 | `json.dump(f, ensure_ascii=False)` | 默认 ASCII 转义 |
| HTTP 请求 | `json.dumps(...).encode("utf-8")` + `charset=utf-8` | 直接丢 dict |
| 文件读取 | `encoding="utf-8-sig"` | `utf-8`（BOM 变 `\ufeff`） |
| Windows 控制台 | `$env:PYTHONIOENCODING="utf-8"` | 不设（乱码） |

> 这套规范已固化为 `scripts/check_encoding.py`，发布前自动执行。
